# 01 Design Direction Contract

## Purpose

Define the visual and content rules before implementation so the project does not drift into random design changes.

## When To Use It

Use after project inspection and before the first implementation pass.

## Prompt Text

```txt
Create a design direction contract for this static business website.

Do not implement yet.

The goal is a premium launch-ready website for:
[describe company, audience, and business offer]

Reference top-tier websites for presentation patterns only. Do not copy content, claims, layouts, or branding.

Define:

- Overall aesthetic direction
- Typography direction
- Logo/wordmark treatment
- Color and surface system
- Hero approach
- CTA hierarchy
- Card rules
- Image and visual rules
- Motion and interaction rules
- Page rhythm rules
- Dark mode rules
- Content tone
- What must be avoided

Keep the result practical and implementation-ready.
```

## Expected Output

- Short design contract.
- Clear do/don't rules.
- Reusable visual system direction.
- Content tone guidance.
- Acceptance standard for implementation.

## Validation Requirements

No build validation is required. Human approval is required before implementation begins.
