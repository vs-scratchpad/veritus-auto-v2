# Handoff Checklist

Use this when handing a static business website to the business owner, reviewer, or next engineer.

## Project Summary

- State what the website is for.
- State the target audience.
- State the primary visitor action.
- State the final deployment URL.
- State whether the site is public-indexed or intentionally noindex.

## Files And Structure

- List main pages.
- List reusable component groups.
- List where global layout/header/footer live.
- List where theme/style files live.
- List where public images/logos live.
- Link to technical appendix if available.

## Content Review

- Identify placeholder copy.
- Identify placeholder address or business details.
- Identify placeholder proof, metrics, or case-study material.
- Identify claims that require business approval.
- Confirm no fake clients, partnerships, or trust claims are present.

## Visual Review

- Attach or reference final screenshots.
- Confirm desktop, tablet, mobile, and dark mode were checked.
- Note any remaining visual compromises.
- Note any assets that should be replaced later.

## Operations

- Document how to run locally.
- Document how to validate.
- Document how deployment works.
- Document who owns future content changes.
- Document who approves public launch changes.

## Final Checks

- `npm run check` passed.
- `npm run build` passed if source/config/deployment files changed.
- Deployment URL opens.
- Navigation works.
- Contact flow is understood.
- Remaining risks are documented.
