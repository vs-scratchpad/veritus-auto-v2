# Veritus Static Website Process Package

## What This Package Is

This package documents the repeatable process used to create the Veritus static website and turns that process into reusable prompts and checklists for future premium business websites.

It is not a redesign brief and not a code manual. It is a practical operating package for planning, building, reviewing, deploying, and handing off static websites with a higher visual standard.

## Read This First

Start with [veritus-static-website-delivery-pipeline.md](./veritus-static-website-delivery-pipeline.md).

That document explains the business-facing delivery process: how to move from brief to design direction, implementation, visual QA, deployment prep, and final handoff.

## What The Delivery Pipeline Covers

The delivery pipeline document explains:

- Why the early Veritus attempts were trial-and-error.
- What changed in the successful final version.
- The repeatable website delivery pipeline.
- Reusable Veritus decisions, such as Geist Sans, white-first surfaces, restrained motion, and system/interface visuals.
- What should not be repeated in future projects.
- Suggested Codex prompt sequence.
- Visual QA and deployment checklists.

## What The Engineering White Paper Covers

Use [veritus-engineering-white-paper.md](./veritus-engineering-white-paper.md) as the technical appendix.

It explains the Astro static site as an engineering system: source files, configuration, routes, metadata, assets, build output, GitHub Pages deployment, and deterministic workflow nodes.

Read it when engineering detail matters, such as debugging base paths, metadata, content collections, build behavior, or deployment output.

## How This Helps Future Projects

The package helps future static website projects by giving the team:

- A repeatable sequence instead of vague "make it look good" work.
- Copy/paste-ready Codex prompts for each stage.
- Checklists for visual QA, deployment, and handoff.
- A clear split between business/design review and engineering validation.
- A reminder that build success is not the same as launch readiness.

## What Remains Human-Reviewed

Human review is still required for:

- Business positioning and target audience.
- Reference website interpretation.
- Design direction approval.
- Visual taste and brand fit.
- Placeholder content, claims, address, and social links.
- Screenshots across desktop, tablet, mobile, and dark mode.
- Final launch decision.

Codex can implement, inspect, and validate. Stakeholders still decide whether the website represents the business well.
